## Implemented contract

The owner-facing Inbox now preserves the asynchronous event contract instead
of presenting an agent call as synchronous chat:

- initial customers are validated server-side and fetched directly from the
  private API;
- browser reads and mutations cross the exact Next BFF allowlist only;
- text, JPEG/PNG/WebP, and OGG/WebM/WAV/MP3/MP4 input share a stable client-
  generated `event_id` and return an HTTP `202` receipt;
- media is rejected before base64 encoding when unsupported, empty, or larger
  than the backend's decoded 6,000,000-byte ceiling;
- an uncertain handoff can retry the identical payload with the same event ID;
- polling is one second while the durable worker outcome is outstanding, five
  seconds when idle, and disabled while the page is hidden;
- persisted inbound receipt and completed outbound reply are separate visible
  states;
- the expandable execution receipt shows bounded node path, elapsed time,
  measured turn cost, event identity, and suspension without exposing prompts
  or secrets;
- explicit microphone start/stop and attached-audio fallback are available;
- “Start a new day” explains that the audit thread remains visible, pending
  refund invocations resume in their original session, and Memory Bank may
  carry only allowlisted trusted usuals—not raw history, prices, payments, or
  authority claims.
